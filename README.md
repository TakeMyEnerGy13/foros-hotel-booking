# Берег Радости

Сайт гостиницы в Форосе. Гость выбирает даты, видит полностью или частично свободные номера и оставляет заявку на трёхчасовой резерв. Администратор подтверждает и отменяет бронирования. В этом репозитории находится полное приложение на Next.js, TypeScript, Prisma и PostgreSQL.

На Fornex доступны [основная версия](https://foros-test.217.194.148.68.sslip.io:88/) и [версия по макету Figma](https://foros-test.217.194.148.68.sslip.io:88/riviera/). Выбор дат в этой версии демонстрационный.

[Открыть «Берег Радости»](https://takemyenergy13.github.io/foros-hotel-booking/)

Главная, каталог, фотогалерея и четыре страницы номеров используют компоненты основного сайта. На Pages календарь показывает вымышленные периоды занятости на ближайшие два года. Гости могут выбирать даты и смотреть стоимость. Заявки и персональные данные сайт на Pages не принимает.

## Первый запуск

Понадобятся Git, Node.js 22.22.2 с npm и работающий PostgreSQL. Версия Node записана в `.nvmrc`. Команды ниже выполняются в корне проекта.

1. Клонируйте репозиторий. Если получили архив исходников, распакуйте его и перейдите сразу ко второму шагу.

   ```sh
   git clone https://github.com/TakeMyEnerGy13/foros-hotel-booking.git
   cd foros-hotel-booking
   ```

2. Создайте отдельную пустую базу для разработки и тестов. Например, следующая команда использует локальную роль `postgres` и запросит её пароль. Можно воспользоваться собственной ролью с правом создания баз или создать базу через pgAdmin.

   ```sh
   createdb -h 127.0.0.1 -U postgres -W foros_test
   ```

3. Скопируйте `.env.example` в `.env` командой `Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в macOS/Linux. Заполните три значения.

   | Переменная | Что указать |
   | --- | --- |
   | `DATABASE_URL` | Адрес созданной базы. Замените `YOUR_ROLE` и `YOUR_PASSWORD` на данные своей роли PostgreSQL. Специальные символы в пароле закодируйте для URL. |
   | `ADMIN_PASSWORD` | Собственный пароль для входа на `/admin`. |
   | `ADMIN_SESSION_SECRET` | Случайный ключ длиной от 32 символов. Новый ключ можно получить командой ниже. Его замена завершает ранее выданные сессии администратора. |

   ```sh
   node -p "require('node:crypto').randomBytes(32).toString('hex')"
   ```

   Для нового клона достаточно одного `.env`. В существующих копиях Next.js и npm-скрипты также читают `.env.local`, а Prisma CLI по умолчанию читает `.env`. При использовании обоих файлов проверьте, что `DATABASE_URL` указывает на одну базу. В Git включён только шаблон с пустыми секретами.

4. Установите зависимости из lock-файла, примените схему и запустите сайт.

   ```sh
   npm ci
   npx prisma db push
   npm run seed
   npm run dev
   ```

   `seed` создаёт четыре демонстрационных номера. Повторный запуск на заполненной базе завершается с ошибкой и сохраняет имеющиеся записи. Для последующих запусков достаточно `npm run dev`.

5. Откройте главную, перейдите в каталог и выберите номер. В админку войдите с `ADMIN_PASSWORD` из своего `.env`. [Главная](http://127.0.0.1:3000/) · [Каталог](http://127.0.0.1:3000/rooms) · [Админка](http://127.0.0.1:3000/admin)

## Проверка изменений

Оставьте сайт запущенным на тестовой базе и во втором терминале выполните команды ниже. Интеграционные тесты обращаются к сайту по HTTP, работают с локальной PostgreSQL и удаляют свои тестовые записи. Имя базы должно заканчиваться на `test` или `preview`. Для проверки повторного заполнения роли нужно право создавать схемы в этой базе.

```sh
npm run test:bookings
npm run test:seed
npm run lint
npm run build
```

По умолчанию тесты обращаются к `http://127.0.0.1:3000`. Если порт занят, запустите сайт командой `npm run dev -- --port 3100` и добавьте `TEST_SITE_URL=http://127.0.0.1:3100` в `.env`. Готовую сборку запускает `npm start`. Полное приложение требует Node.js и PostgreSQL. При размещении в production нужен HTTPS для cookie гостя и администратора.

Для ручной проверки откройте страницу номера и админку в двух окнах. Оставьте заявку, обновите страницу гостя и откройте «Детали заявки». Подтвердите заявку в админке — у гостя появится «Бронь подтверждена», таймер исчезнет. После отмены даты снова станут доступны. Изменения вносите в отдельной ветке и вливайте в `main` через PR после проверок.

Даты поиска задают заезд и выезд. В день выезда может заехать следующий гость. В календаре номера клик выбирает ночь, второй клик заполняет интервал, если все ночи внутри него свободны. Новая гостевая заявка в базе получает статус `held`, а до дедлайна отображается как `pending`. Сервер вычисляет истечение срока при чтении. Подтверждённая бронь продолжает занимать ночи. Для старых и вручную созданных записей `pending` автоматическое трёхчасовое ограничение не применяется.

Новые гостевые заявки восстанавливаются в том же браузере через HttpOnly cookie. Открытая админка и страница гостя с заявкой получают актуальный статус при возврате во вкладку и каждые 10 секунд, пока она видима.

Телефон Ольги и ссылки Telegram и MAX пока демонстрационные по решению владельца. Перед приёмом реальных заявок получите актуальные контакты. [Телефон](src/lib/booking-contact.ts) · [Ссылки](src/components/ContactServices.tsx)

Файл `fix.js` в корне — старый одноразовый скрипт, который перезаписывает галерею. Актуальная галерея редактируется в компоненте. [Gallery.tsx](src/components/Gallery.tsx)
