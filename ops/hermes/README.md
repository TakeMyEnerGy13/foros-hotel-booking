# Обслуживание редактора гостиницы

[Памятку для человека, который меняет сайт](../HERMES-TRIAL.md), можно пересылать целиком.

## Как устроен доступ

Один Telegram-бот обслуживает несколько личных чатов. В основном конфиге Hermes на Fornex включён параметр `gateway.multiplex_profiles`. Правило в `gateway.profile_routes` направляет конкретный личный чат в профиль `hotel-editor`. Правило одновременно проверяет `platform: telegram`, числовой `user_id` отправителя и такой же `chat_id`. Имена и числовые идентификаторы владельцев хранятся на сервере.

Когда владелец попросит подключить следующего редактора, сверьте с ним числовой ID. Добавьте отдельное правило для личного чата и включите ID в `TELEGRAM_ALLOWED_USERS`. Права на административные команды задаёт `telegram.allow_admin_from`, а доступ из групп задаёт `telegram.group_allow_from`. Редактору достаточно доступа в личном чате. После подключения проверьте обычный вопрос к Codex и доступ к рабочей копии сайта.

## Как изменения попадают на сайт

Правила общения и работы находятся в [SOUL.md](SOUL.md). После их изменения обновите файл в профиле `hotel-editor` на сервере и проверьте ответ в новом диалоге. Профиль работает через SSH от имени `foros-edit` в каталоге `/srv/foros-hotel-test/source`, в ветке `owner-trial`. Вложения доступны в каталоге этого пользователя. Для сборки доступны команды `hotel-trial preview` и `hotel-trial status`.

Адрес из памятки показывает сборку `draft`. Старые ссылки на второй адрес перенаправляют туда же и сохраняют путь до страницы. Чтобы вернуть правку, отмените её отдельным коммитом, повторите `hotel-trial preview` и проверьте изменённую страницу. Значение `draft` в выводе `hotel-trial status` должно совпадать с `git rev-parse HEAD` в рабочей копии.
